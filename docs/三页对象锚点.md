# 三页对象锚点（通讯录 / 发现 / 我）

> 2026-11-25 真机探针结果（`PageProbe`，tag `WeChatGlassProbe`）。原则：**找对象，不找名字**。
> 类名/资源 id 只作为“进入对象图的入口”，拿到对象后一律用框架 API 操作该对象。
> 原始日志：`debug/probe_all.txt`、`debug/probe_contacts3.txt`、`debug/probe_pref.txt`。

## 1. 入口：从 pager 对象拿到页面对象

已持有对象：`HomeGlassHook.pagerView`（`WxViewPager`）。

```
pagerView (WxViewPager)
├─ getAdapter()                         ← PagerAdapter 对象（hook instantiateItem 拿页面对象）
└─ getChildAt(0..3)  → 4 个 com.tencent.mm.ui.FrostedContentView（id 0x7f0a49e8）
   顺序固定：[0] 微信 / [1] 通讯录 / [2] 发现 / [3] 我
```

每个 `FrostedContentView` 内部结构（对象链）：

```
FrostedContentView
└─ MMWeUIBounceView (id 0x7f0a49ff)
   ├─ NestedScrollView
   └─ FrameLayout                      ← 真正的页面内容宿主，我们的页面挂这里
      └─ MainUIView / WxRecyclerView / RelativeLayout(...)
```

实测要点：

- **页面对象会重建**：切 tab 后 `FrostedContentView` 的 identityHashCode 变（例：`31888166` → 新对象），
  所以我们的覆盖页必须能“按页面对象”重挂，不能只挂一次。
- **adapter 异步就绪**：页面刚创建时 `getAdapter()` 返回 `null`，约 1–2s 后才有；
  页面对象 dump 要在切页后延迟重试（探针已用 900ms / 2200ms 两次）。
- `instantiateItem(ViewGroup, int)` 的返回对象即页面对象，`destroyItem` 可用来清理我们的覆盖页。

## 2. 微信（tab 0，已有实现，仅记录）

- 列表对象：`ConversationListView`（id `0x7f0a472d`），adapter `android.widget.HeaderViewListAdapter`，
  `count=31`，`mHeaderViewInfos=14`，`mFooterViewInfos=1`。
- 原生点击监听对象：`com.tencent.mm.ui.conversation.i3`（长按 `t3`）。

## 3. 通讯录（tab 1）

| 项 | 对象 / 值 |
|---|---|
| 列表对象 | `com.tencent.mm.view.recyclerview.WxRecyclerView`（id `0x7f0a0262`） |
| 字母索引对象 | `AlphabetScrollBar`（id `0x7f0a0272`） |
| adapter | `su3.y1`，`count=36` |
| adapter 数据 | 字段 `data` List size=34，**34 项全是同一个 `bq5.g` 占位对象** |
| 点击监听 | `mOnItemClickListener = null`（RecyclerView，没有列表级 listener） |

结论：
- 这是**分节（section）型 adapter**：`bq5.g` 是占位/多类型 item，单条联系人数据不从这里暴露；
  硬拆它需要再往下挖 `v`/`w` 两个 Map 和 `i`/`m` 两个列表，收益低、易碎。
- 该页点击只能走 `recyclerView.findViewHolderForAdapterPosition(pos).itemView.performClick()`，
  要求我们的行与原生 adapter position 一一对应（自建 A–Z 分组会破坏这个对应关系）。
- **因此通讯录采用：数据来自 `ConversationIndex`（只读 SQL，已有）+ 点击走已跑通的打开会话/资料页**；
  不再尝试从 `su3.y1` 抽单条联系人。

## 4. 发现（tab 2）

| 项 | 对象 / 值 |
|---|---|
| 列表对象 | `com.tencent.mm.ui.widget.listview.PullDownListView`（id `0x102000a`） |
| adapter | `com.tencent.mm.ui.base.preference.g0` |
| count | 9 |
| `getItem(0)` | `com.tencent.mm.ui.FriendSnsPreference`，`toString = [モーメンツ]` |
| 标题 | Preference 对象字段 `h`（=「モーメンツ」），等价 `getTitle()` |
| 图标 | 字段 `i` = 图标资源 id（2131775891），等价 `getIcon()` |
| 行布局 | 字段 `F` = layout id |
| 点击 | `PullDownListView` 自己就是 `mOnItemClickListener`，用 `list.performItemClick(view, pos, id)` 原样转发 |

结论：发现页可以**完全对象化**——遍历 `adapter.getItem(i)` 拿 Preference 对象（标题/图标/摘要），
点击用 `performItemClick`。不需要硬编码条目、不需要文本匹配、不需要猜 Intent。

## 5. 我（tab 3）

同一套 `PullDownListView` + `g0`，`count=13`：

| 索引 | 对象 | 数据 |
|---|---|---|
| 0 | `com.tencent.mm.pluginsdk.ui.preference.AccountInfoPreference`（`[プロフィール]`） | `K` = `wxid_...`（username）、`L` = `paw_milk`（微信号）、`J` = 昵称 SpannableString、`M`/`N` = 头像 ImageView、`X` = 昵称 TextView、`x1` = `MoreTabUI$13`（点击回调） |
| 1..12 | Preference 行 | `h` = 标题，`i` = 图标资源，`F` = 布局 |

结论：我页的资料卡数据（昵称/微信号/头像）**直接从这个 Preference 对象读**，不用遍历 TextView；
入口行点击同样 `performItemClick`。二级页面（支付和服务、收藏、作品、商店、表情、设定）保持微信原生。

## 6. 顶栏（顺带确认）

AppCompat 的 `ActionBar` 对象可从 activity 拿到（`getSupportActionBar()` → `getCustomView()`），
可替代现有 `Ui.findByClass(decor, "androidx.appcompat.widget.ActionBarContainer")` 的名字查找。
改动前需回归首页顶栏（overlay 的几何依赖 `actionBarHeight` 与 `actionBar.getTop()`）。
